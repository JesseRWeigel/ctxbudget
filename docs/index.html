CJK, measured on its own

The band above comes from a corpus that is mostly ASCII code and does not describe a file of Japanese, so the tool quotes a separate number once an input is at least 10% Han, Kana or Hangul. That number cannot come from the sampled corpus: of 1260 files in it, 0 reach that share, because the machine holds Japanese UI strings inside TypeScript files and no Japanese documents. It is measured instead on the committed CJK fixtures, which sit outside the fit.

Three short documents is a thin measurement and the page says so rather than implying a corpus stands behind it. Korean is what forced it: priced at the Han and Kana rate it came out up to 35% high, and it now has its own class fitted on 66 training chunks. The classes the corpus barely reached are word_cjk_px, word_hangul, word_hangul_px, word_hangul_sp, word_wide, word_wide_px, and the count behind each one is in class_support in the committed table.

Rank by tokens / ((1 + inbound refs + task match) × (1 - redundancy)), which is tokens returned per unit of demand that would actually be lost. What is not measured

  • Claude has no public tokenizer. Claude counts here use the cl100k_base table as a stand-in and are labelled unmeasured with no error band.
  • Context windows and reply caps come from vendor documentation read on 2026-08-15, not from anything this project measured. Override them with --window and --reserve.
  • CJK is measured on three committed fixtures and not on a corpus, because this machine has no CJK documents to hold out. The tool quotes that measurement, with its file count, whenever the input crosses the threshold.
  • The cut ranking reads structure, not meaning. A file can matter for a reason no import graph records, so the tool prints the counts behind every rank and removes nothing on its own.

Setting a long context on Ollama

Measured on the development machine on ollama 0.32.9: only options.num_ctx in the API request body changes the loaded context length. /set parameter num_ctx in the REPL and OLLAMA_CONTEXT_LENGTH in the client shell both leave the server default in place and report no error, so a run you believe has 128k may be truncating. Check ollama ps.
